# Test Plan — E-Commerce Web Application

## 1. Project Information

Project Name: E-Commerce Web Application — Manual Testing  
Application Under Test: SauceDemo  
Website: https://www.saucedemo.com/  
Testing Approach: Manual Testing  
Project Level: Beginner / Fresher Portfolio Project  
Duration: 21 Days (Self-paced)
Version: 1.0

## 2. Project Objective

The objective of this project is to test the main shopping workflows of an e-commerce web application and verify whether its features work as expected.

The project will help develop practical skills in requirement analysis, test scenario design, test case writing, test execution, defect reporting, and QA documentation.

## 3. Scope of Testing

The following features are included in the project:

1. Login and authentication
2. Product listing and product information
3. Product sorting
4. Adding and removing products from the cart
5. Shopping cart details
6. Checkout workflow
7. Order summary and order completion
8. Logout

Out of Scope:

- Real online payments
- Performance and load testing
- Security penetration testing
- User registration, if it is not supported by the application
- Automated testing

## 4. Testing Types

The following testing types are considered in this project:

- Functional Testing: Checking whether features work as expected.
- Smoke Testing: Checking the most important features to see whether the application is ready for further testing.
- Positive Testing: Checking the application with valid inputs.
- Negative Testing: Checking how the application handles invalid inputs.
- UI Testing: Checking visible elements, labels, buttons, and layout.
- Exploratory Testing: Exploring the application to understand its behaviour and discover potential issues.
- Regression Testing: Rechecking relevant features after a change or fix, if a suitable change is available.
- Retesting: Testing a reported defect again after it has been fixed, if a fix becomes available.

Only testing activities actually performed will be recorded as completed.

## 5. Test Environment and Tools

- Application: SauceDemo demo website
- Browser: A desktop web browser
- Test Documentation: Excel, Google Sheets, or Markdown files
- Evidence: Screenshots, where useful
- Version Control: Git and GitHub
- Test Data: Demo login credentials and sample checkout information

## 6. Testing Approach

1. Explore the application and understand its features.
2. Identify the requirements and user workflows.
3. Prepare test scenarios for each feature.
4. Write detailed test cases with test data and expected results.
5. Execute the test cases manually.
6. Record actual results and mark each test as Pass, Fail, or Blocked.
7. Investigate failures and document reproducible defects, where applicable.
8. Capture screenshots or other evidence when useful.
9. Prepare the final test execution summary based on the actual test results.
10. Upload the project documentation to GitHub.

## 7. Entry Criteria

Testing can begin when:

- The demo website is accessible.
- The tester understands the feature being tested.
- Suitable test data is available.
- The basic test environment is ready.

## 8. Exit Criteria

The project can be considered complete when:

- Planned test scenarios and test cases have been documented.
- The planned tests have been executed as far as the environment allows.
- Actual results and test statuses have been recorded.
- Any identified defects have been documented with supporting evidence where possible.
- A final test summary has been prepared.
- Project files have been organized and uploaded to GitHub.

## 9. Deliverables

The project is expected to contain:

- Test Plan
- Requirements and Application Flow
- Test Scenarios
- Detailed Test Cases
- Test Execution Summary
- Defect Analysis and Bug Report
- Screenshots or other test evidence, where useful
- GitHub repository with a README file

## 11. Risks and Limitations

- The demo application may have predefined behaviour or intentional limitations.
- Some defects may not be reproducible or may not be present.
- Real payment processing and production customer data are not part of this project.
- Regression testing and retesting depend on whether a suitable application change or fix is available.
- The project duration may change if additional investigation is required.

## 12. Completion and Reporting

The final report will summarize the tests planned, tests executed, pass/fail/blocked counts, any confirmed defects, limitations, and recommendations.

All reported results will be based on actual observations. No defects, execution results, or testing activities will be claimed unless they were genuinely performed.
